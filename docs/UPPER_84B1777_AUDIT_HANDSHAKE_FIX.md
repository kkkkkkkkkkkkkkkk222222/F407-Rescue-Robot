# 发给上位机Codex：84b1777之后的审核握手修正

请基于上位机 `codex/gamepad-teleop@84b1777` 及当前后续代码做增量修正。
保留现有改动，尤其是侧装T265参数；不要整套重套旧0007补丁。
下位机本次在F407 `76f69b1` 基础上修改Task；部署前核对包含本契约的新固件版本，尚未实车烧录。

## 一、下位机已经修改的契约

### 双方稳定后才放行

- 普通、聚集、分离复审、mode23/45/48：三个不同真实audit_id、本地有效采样间隔
  至少100ms，再收到上位机当前审核的STABLE，才上报AUDIT_READY。
- AUDIT_VALID同时要求上述条件及既有类别、数量、首件、目的地合法性。
- mode43仍为受控扫障非空规则，但同样要求本地三帧及上位机STABLE。
- 上位机应先独立按图像采集时间完成稳定判断并发送STABLE，再等READY/VALID。
  禁止先等待READY再置STABLE，避免循环等待。
- MCU收到三次相隔100ms的非STABLE审核，即使都合法，也不会进入mode49/50/22/40，
  不授权GRAB/NAV/ALIGN。普通及聚集捕获已收齐本地三帧时保持停车等待确认。
- 同一最新视觉帧、audit_id、完整载荷的STABLE重发可确认既有本地三帧结果，
  不能增加计数或续期；陈旧/不匹配帧不能确认。mode43请继续消费新真实帧到双方确认。

### 无观察占位包

- vision_frame=0，左右类别NONE，左右计数与总数0，STABLE=0，危险/未知/混装标志0，
  才是占位。audit_id可保留，不构成新证据。
- 通用占位的audit_flags全零，可以在mode43及伤员mode45得到ACK；下位机将其作为
  心跳，不改变原载荷角色和目的地。兼容范围不包含真实非零帧或错误角色的真实审核。
- 正确带阶段角色标志的占位仍可使用；明确错误角色标志仍拒绝。上位机最好保留
  mode43的SWEEP_PICKUP和伤员找回的DESTINATION_INJURY，以便诊断。
- 活动审核中收到占位，清除旧证据、READY/VALID和旧审核完成状态；不计空爪。
- mode49/50机械阶段、mode22/40等待交接阶段只ACK占位，保留已确认快照。
- STABLE=1但vision_frame=0，或frame=0且存在非零物资证据，按非法请求拒绝。
- 占位、新action或证据过期均不能重置扫障原有3.5s窗口或15s总期限。

### 有限交接等待

- mode22等待NAV、mode40等待ALIGN也纳入15s固定等待期限。
- 持续心跳不延长；到期释放并执行现有mode24恢复。mode22普通恢复后回SEARCH；
  mode40恢复经mode47请求RETURN_CENTER。其它既有返中条件保持。
- 人工PAUSE期间不会自行启动恢复；保留现有通信、IMU、显式STOP/ABORT处理。

## 二、上位机必须修改的部分

### 1. 修复扫障回执等待

`_safe_sweep_pickup_output`的占位应明确角色，实际非零mode43审核必须置SWEEP_PICKUP；
伤员原物资mode45及扫障后mode23目的地标志必须与原货物一致。
`_output_for_cycle`不能在context_pending时冻结mode43/45的视觉决策。
同任务、新鲜状态下，CLEAR_SAFE_ZONE的审核状态也应重新检查新帧和当前真实阶段。
消费0x1E明确拒绝时核对task_id、rejected_action_id，不凭旧ACK推测接受。
mode43/45回退到42/44后，应恢复APP/HOLD目标查找，不能永远重发旧CARGO_AUDIT。
不得因重建请求而重启已接受的机械动作或重置扫障前进预算。

### 2. 缺失pending审核必须有出口

mode50只保留已经接受的第二轮合法结果，不重新审核或提前NAV。
若见到mode50/22/40而本地没有对应pending审核，不得根据selected_batch猜实际载荷，
也不得一直发送占位而关闭看门狗。保持无观察心跳，等待下位机15s恢复，明确记录
missing_committed_audit；17s仍未恢复则报告握手超时并ABORT。
异常等待看门狗要覆盖22/40，即使本地批次已丢失也不能自动失效。
正常看到22/40且pending、上下文、闭爪、READY/VALID齐全时立即交接。
mode24/47/17/3按现有流程清理上下文及恢复。人工暂停应与协议异常等待区分。

### 3. 统一非法审核签名

以编码后实际发到串口的字段为准：

```text
(total_count, audit_flags去STABLE, 类别计数直方图, 零数量非NONE类别掩码)
```

类别直方图按线上的类别0..6累计两侧计数，忽略左右侧交换及track ID。
零数量但类别不为NONE的侧，按类别置掩码位，保持异常载荷可区分。
MIXED_MATERIAL保留独立类别；left_green_count等信息没有在线上传输，不能擅自
展开成与GREEN/CORE分侧相同的签名。普通/核心、数量或非法标志变化均重计数。
比较编码后字段时保留原始total_count，不能为了与左右饱和计数相等而裁剪真实总数。
INITIAL_STASH非空仍使用STASH_NONEMPTY，mode43仍为扫障非空例外。
正常合法的单件、首件、伤员及目的地规则不变；MIXED正式运输仍非法。

### 4. 修复藏堆/扫障质量筛选

当前`make_vision_snapshot`对所有目标统一做重叠/边缘检查，会把藏堆的任意非空
例外挡在审核之前。INITIAL_STASH保留图像有效、相机就绪和ROI已标定检查，但有
真实目标的非空堆不能仅因数量多、类别混合或重叠而被替换为None。
不能在没有任何检测证据时伪造total_count=1。缺图、全黑/过曝等仍为无观察。
mode43质量判断应针对本次扫障目标及可观察性，避免无关物资遮挡阻断受控非空取障。
正式运输的mode23/45/48仍保留严格截断、ROI完整及遮挡检查。

## 三、保持原要求

- 伤员流程仍为23→49半闭爪后退→23二次复核→50闭爪→22导航。
- 81°/99°、后退2s、140°稳定500ms、预备点mode48和原机械路径保持。
- 单件数量限制、首件条件、投送超时/TASK_COMPLETE及投送计数保持。
- MG310霍尔1061.268计数/轮、70mm轮、稳压12V、55%PWM保持。
- 原PID保持6/0.15/0、修正±450、积分±2500、MoveSpin倍率1.8。
- 不增加堵转、反向计数、无进度引起的自动联停。保留原让行、换道及脱困。
- 不擅自修改侧装T265外参、纯T265/融合选择和现有串口配对协议。

## 四、验收

1. 图像采集90ms间隔、串口接收100ms间隔：双方未确认前，MCU不得提前闭爪/导航。
2. STABLE单帧或重复帧不能跳过三帧；同帧确认不续期，不匹配旧帧不能确认。
3. mode43及伤员mode45首次占位ACK，后续真实帧能进入审核；真实错误角色仍拒绝。
4. context_pending时新帧/明确拒绝可推进恢复，不能在42/44无限重发旧审核。
5. 两普通/两核心交替必须重计数；左右交换同类别同数量保持连续。
6. 两个重叠目标可按INITIAL_STASH非空处理；正式运输仍按原规则拒绝。
7. mode50保留结果；无pending的22/40有15s恢复、17s异常出口，不伪造投送成功。
8. 占位不累计空爪、不续期、不改变角色；READY/VALID只在双方确认后成立。
9. 更新旧测试的帧号、采集时间、上下文和STABLE夹具，不通过放宽业务规则让测试过。
