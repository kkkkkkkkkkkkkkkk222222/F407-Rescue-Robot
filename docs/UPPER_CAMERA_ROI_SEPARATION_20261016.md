## 2. ROI恢复旧版逐物体筛选，比例统一60%

涉及competition_rescue/run_competition_rescue.py、capture_roi.py。

保留用户标定的overall/left/right多边形、坐标缩放与底部中心归属规则，统一使用0.60的框面积重叠比例，不再给绿色单独设0.80。

重点修复make_vision_snapshot：当前代码即使已用0.60，仍会因某个框仅有20%至60%进入ROI，或图像边缘截断框与ROI有一点交集，就将整幅capture_observation_valid置为False。这不是旧版的逐物体纳入语义。

恢复旧版做法：逐个目标判定是否满足ROI纳入条件，不满足者不进入爪内清单；爪外、不合格的边缘框不能清空其它清楚目标的审核。不得只统计selected_batch，所有实际满足爪内条件的可见物体都要进入真实计数，不能漏掉额外物块以制造合法运输。

重叠、多件、已知类别混合不再统一等价于“没有观察”。分离决策可以使用有明确类别和侧别的混合检测；正式运输仍检查实际类别、单件限制及可靠性。真正无法分辨的遮挡不能伪造成单件。缺图、全黑、过曝、未标定ROI、相机未就绪仍是无有效观察，不是空爪或非空堆。

INITIAL_STASH继续采用真实非空堆语义；mode43按本次扫障目标判断，不让无关物资重叠阻断。伤员取回及正式运输审核保留真实全爪清单和角色标志。

标定文件目前在启动时加载；只改磁盘文件不会更新进程内ROI。保留现有加载方式时须重启，且显示叠框和审核必须使用同一个ROI对象。

## 3. 多物块可分离，优先保留绿色最多的一侧

涉及run_competition_rescue.py的audit_from_cargo，以及state_machine.py的_side_is_disperse_candidate、_preferred_keep_side和侧别投票。

当前绿色+橙色等同侧已知组合会压成unknown，并被left/right_invalid挡住，最终退化为无选侧20度观察。请在上位机内部保留逐侧真实类别组成，区分“多个已知类别混合”和“真正识别未知”。为分离建立独立的候选资格，不用正式运输的合法条件直接否决所有混合侧。

例如一侧明确有绿色和橙色，可作为保留绿色的受控分离候选，但审核仍报告真实混合/非法载荷，不得改写为纯绿色，不得以此直接运输。危险物、真正未知及无法确认左右归属继续使用已有处理，不盲目强夹。

两侧都有绿色时优先保留绿色数量较多的一侧。已核对版本在left_green != right_green时使用了left_green < right_green，实际选择更少侧，需要反向。相同时优先保持当前已锁定侧，再参考无关物块更少的一侧，最后固定侧作为确定性回退，避免左右反复跳动。没有绿色时沿用本轮目标类别和目的地选择规则，不把伤员任务改成物资运输。

选侧使用两个不同新帧稳定确认，采集间隔至少100ms。可将“侧别稳定”与“该侧精确件数不变”分开处理：数量变化不得伪造审核稳定，但不必仅因强夹档位而重置全部选侧，因为下位机现已统一10度。侧别证据必须与最终本轮审核一致。

## 4. 确保实际进入曲线分离

涉及state_machine.py的_arm_disperse和首次绿色轻推分支。

已有可靠选侧时，发送DISPERSE_PILE + SIDE_VALID；保留右侧再带TARGET_RIGHT，保留左侧清除TARGET_RIGHT。维护有效的cluster_keep_side_count，避免_arm_disperse因旧值为0将已选侧退回None。

下位机收到带选侧命令才进入现有“非保留侧开爪、保留侧额外夹紧10度、短弧后退、锁航向继续后退、140度复核”流程。没有SIDE_VALID会走20度观察转向，不能把它记录成已经执行曲线分离。

可靠选侧存在时，不应再被FIRST_GREEN_BUMP覆盖成无选侧轻推。首件必须为绿色等比赛规则仍保留；只是改变分离动作选择，不放宽首件运输规则。

分离次数按下位机实际接受的物理动作累计，重发、等待回执、占位审核和单纯观察转向不能误计为一次分离。第一次后重新取新画面，仍有可分离候选则进行第二次；第二次真实复核仍失败才使用现有放弃/返中心流程。收到本地等待恢复时退出旧上下文，不无限重发动作，不新增通用escape命令。
