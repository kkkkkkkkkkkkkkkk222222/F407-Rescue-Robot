## 下位机已修改

1. NormalRun 在运行中 IMU ready 变为 false 后仍执行主任务，先处理收到的指令，再进入停车故障并持续上报。普通轮速目标不再因为任务被跳过而残留。使用现有 `TASK_FAULT_POSE_TIMEOUT=5` 和 mode18，不增加线上故障码。码5表示定位不可用，并不唯一代表 IMU 故障。IMU 运行故障本身锁存，需要检查连接、静止复位重新初始化，不能靠 HOLD 解除。
2. 远程有限动作的 PAUSE/HOLD 停车保留原始编码器位置、陀螺仪角度及执行状态。恢复同一动作时只完成余量；转动暂停时间不计入原有转动超时。停止惯性产生的编码器/角度变化仍计入总进度。STOP、ABORT、取消或切换状态仍彻底取消动作。HOLD 对 DISPERSE 的1秒取消计时与人工 PAUSE 分开，保留原有取消语义。
3. PAUSE 期间冻结审核15秒看门狗及相关决策/相机等待/取回预算时间，恢复前先补偿暂停时长。图像采样和证据有效期不被冻结、不续期；恢复审核要有新鲜图像。mode50、22、40已提交审核快照的原有保持逻辑不变。普通 HOLD/占位审核没有人工暂停待遇，仍受原有超时约束。
4. mode43补发同帧 STABLE 可以确认已有的三个不同 audit_id 样本，但必须是当前上下文最新帧、最新审核ID、完全匹配的线上类别/数量/去STABLE标志，且证据未超过500ms。确认不增帧、不更新时间戳。仍需本地采样间隔至少100ms、真实审核 SWEEP_PICKUP；不放宽角色检查或非空语义。

## 给上位机 Codex 的修改要求

### 1. 故障处理优先于人工暂停和 context_pending

在 `competition_rescue/run_competition_rescue.py::_output_for_cycle` 中，先检查新鲜的下位机故障状态，再走人工暂停、摄像头暂停及上下文等待。不要让人工暂停页面遮住硬件故障。

`competition_rescue/state_machine.py::step` 当前 `stm.fault` 分支仅输出 `f407_fault_wait` 并等待恢复。对于 mode18 的锁存故障，应改成明确的终止/人工干预状态，保留首个故障码、task_id/action_id及故障前阶段，提示检查硬件并复位，不能无限等 ready 自行恢复，不能自动重发配置启动新一轮。

如复用现有 FAULT/ABORT 路径，发送 ABORT 前必须保存首个故障，因为 ABORT 的后续回执可能变为 REMOTE_STOP=1。不要把码5一律显示成“IMU损坏”；显示“定位/IMU不可用”，详细原因依硬件诊断判断。失联状态不能当作新鲜故障处理。

### 2. 暂停恢复沿用同一机械动作

`_publish` 已把 HOLD/PAUSE 作为 overlay，并沿用已接受上下文；保留这个实现。

恢复尚未完成的有限动作时保持原 task_id/action_id、opcode、flags及原始动作参数，不另开动作、不重新执行整段、不由上位机再次扣减距离或角度。下位机已经保留原点和剩余行程。等待当前动作完成回执，再分配下一动作；若明确取消或下位机已恢复/故障，不能强行续接旧动作。

### 3. 保留人工暂停与协议异常的区别

保留 `_audit_wire_timeout_output(..., manual_paused=True)` 的人工暂停补偿；正常审核/缺pending的协议等待继续执行原17秒握手超时。

摄像头恢复当前仍发 PAUSE，但上位机不能因此无期限冻结协议异常期限。下位机无法通过同一个 PAUSE opcode区分来源，因此异常最终仍由上位机超时/ABORT兜底。不要用周期 PAUSE 代替正常的占位审核或 context_pending 请求重发。

恢复观察中的审核时重新使用新鲜画面，不能把暂停前的 STABLE 当作新证据，也不要整体平移图像采集时间/证据有效期。mode50合法pending保持、22/40缺pending恢复、15秒下位机恢复和17秒上位机兜底维持原设计。

### 4. 扫障审核继续独立发布 STABLE

保留 `_safe_sweep_pickup_output` 按 `observed_monotonic_s`、至少100ms间隔、至少200ms跨度完成三帧稳定的逻辑。先发 STABLE，再等当前审核的 READY/VALID，不能倒置。

同一最新帧可重发完全一致的审核并仅补上 STABLE；重发不能分配新 audit_id、伪造新 vision_frame，或延长证据有效期。即使主机已稳定，也继续处理新采集画面；采集90ms/串口接收100ms等不同步情况不能按串口重发数补主机三帧。

保留 context_pending 期间 mode43/45 和 CLEAR_SAFE_ZONE 审核的新视觉与拒绝处理。43回42、45回44后回到 APP/HOLD查找，不能无限重发旧审核或重启已经接受的抓取。真实mode43用SWEEP_PICKUP，45及扫障后23保持原载荷DESTINATION_INJURY。

### 5. 不做顺手改动

保留伤员23→49→23→50→22、mode48预备点复核、单件/首件规则、藏堆/扫障语义、投送计数、投送超时及TASK_COMPLETE。不改变命令0x19、状态0x1A或0x15原始编码器累计计数。

MG310每轮1061.268计数、慢衰减、60% PWM上限、速度PI=5/0.12/0、航向PI=2/0.005/0、视觉车头PD=0.45/0.01及关闭堵转联停全部保持。本次不调整NormalRun独立导航P=20，不把它与轮速PI混为一谈。

不要新增测试程序，也不要重套旧0007等整套补丁；仅做上述增量适配。
