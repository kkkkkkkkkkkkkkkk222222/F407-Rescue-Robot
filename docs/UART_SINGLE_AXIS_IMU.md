# 单轴串口陀螺仪移植（2026-10-21）

## 接口与接线

依据用户资料中的《单轴串口通讯数据手册》和 `STM32F103标准库例程.zip` 的
`Gyro.c/Gyro.h`，将其通信协议移植到当前 STM32F407 HAL 工程。

新模块使用 **USART2，PD5 TX / PD6 RX，115200、8N1，无流控**。
开发板和扩展板原理图均引出了 PD5/PD6，当前固件未将它们分配给其它外设。
USART2 的另一个映射 PA2/PA3 已用于 M1 的 TIM5 PWM，不能照抄 F103 示例接线。

| 新模块信号 | F407 接点 |
| --- | --- |
| VCC | 稳定的 5V 逻辑电源，不能接电机 PWM 输出 |
| GND | GND，与 F407 共地 |
| TX | PD6，USART2_RX |
| RX | PD5，USART2_TX，用于配置输出速率 |

按模块实际丝印核对线序，不依赖线束颜色。使用 TTL UART，不是 RS232/RS485。
资料只标注 TTL，没有明确 TX 电平数值；连接前确认信号电平与 F407 兼容，必要时加电平转换。
模块水平固定，单轴垂直车体旋转平面，物理安装方向按用户确认与原模块一致。

注意：PCB 上现有“串口2”接口实际连接 PA9/PA10，是 USART1，**不是本次新增的
USART2 PD5/PD6**。新模块从扩展排针上的 PD5/PD6 接出。

USART2 由应用驱动 `IMU_Init()` 和 HAL MSP 初始化，不依赖 CubeMX 生成的
`MX_USART2_UART_Init()`；若以后重新生成 CubeMX 代码，需要保留本次 USART2
的 MSP 分支及专用中断入口，不能用通用 `HAL_UART_IRQHandler()` 覆盖该入口。

保留其它接口：USART1 PA9/PA10 为程序器文本调试，USART3 PD8/PD9 为上位机。
不改变电机/编码器/舵机/LCD 引脚，不改变上位机配对协议、PID 或运动极性。

## 驱动与角度

- `APP_IMU_USE_UART=1` 为默认，NormalRun、Gamepad、MotionDebug 共用。
- 原 `imu.c` 的 IMU660RC SPI 驱动保留；将该配置设为 0 可切回，旧驱动未重写。
  SPI3 仍初始化原引脚，但 UART 模式不会读旧传感器；MicroSD 仍须保持空槽。
- `imu_uart.c` 独立初始化 USART2 并处理 RXNE/错误中断，不使用 USART1/3 的
  DMA、文本解析或 HAL 接收回调，不存在每帧接收完忘记重新开启的问题。
- 帧格式：`5A TYPE LOW HIGH SUM8`。AA 为有符号角速度，BB 为有符号角度；
  校验为前四字节和的低 8 位，坏帧滑动搜索下一帧头。
- 单位严格遵循示例：角速度 `raw * 2000 / 32768` 度/秒；
  角度 `raw * 180 / 32768` 度。手册给出的物理量程为 +/-400 度/秒，
  **不能因此将 AA 的协议换算系数改为 400**。
- 直接使用模块内部算法解算的角度；在原始 16 位计数域展开 +/-180 度回绕，
  64 位累计后换算毫度，支持正反向及多圈，不重复积分角速度，不叠加旧 SPI 零偏算法。
- 第一帧角度作为本地零点；`IMU_ZeroYaw()` 只移动软件零点，不向模块发送硬件归零，
  避免破坏正在使用的全局航向。原有运动接口和相对转角语义不变。
- `APP_IMU_UART_YAW_SIGN=1` 默认原样接入角度、角速度，保留既有车体/电机符号。
  同一物理安装方向下，仍应静止手转确认模块协议的正负；若确实相反，只将此值设为 -1，
  它会同时转换角度和角速度，不要分别改 PID、编码器或定位符号。
- 旧 `APP_IMU_GYRO_Z_SCALE_PPM` 只作用于旧 SPI 积分；新模块采用自身标定结果。
  手册宣传角度分辨率与本 UART 定点量化并不相同：BB 的最小步长约 0.00549 度。
  精度仍须实车参考角度验证，编译及模拟协议检查不代表实测精度保证。

## 启动、输出频率与恢复

模块默认 20Hz，上电约 500ms 开始输出。驱动先观察真实 BB 间隔，低于目标速率时
按厂商顺序发送 `55 AA 13 8E 5F`，等待 100ms，
发送 `55 AA 02 0B 00` 配置 200Hz，等待 100ms，再发送 `55 AA 00 00 00` 保存。
这些配置等待在主循环状态机中推进，不在中断中延时。

已达到约 5ms 输出间隔的模块不会每次启动重复保存，减少模块 Flash 写入。
配置仅尝试一次并核对实际输出间隔；失败计入诊断，不新增不可恢复停车锁存。
若需要保留模块原速率，可设 `APP_IMU_UART_AUTO_RATE=0`；过低的频率可能触发
既有转角控制器的 100ms 新样本超时，因此比赛推荐保持自动配置开启。

首次启动最多等待 2 秒；未接线或晚供电不会卡死启动。接收持续运行，后续收到
角度与新鲜角速度、累计三个新角度包后自动恢复 ready，应用也会完成延后的初始化。
这个三个包是陀螺仪链路恢复检查，**不是改变物块累计两帧审核规则**。

150ms 没有新角度或新角速度时报告链路暂不可用。短暂接收错误/短断流可依靠模块
绝对角度自动恢复，不因为一次校验错就锁定航向。间隔达到 300ms 时无法保证
在额定量程并留余量的情况下没有漏过半圈，沿用已有 `heading_uncertain` 和外部航向
重新参考流程；不伪造失联期间的转角，不增加新故障模式。MotionDebug 可在静止、
确认车头参考后发送 `RESET` 建立新参考；NormalRun 沿用现有上位机参考恢复流程。

厂商零偏标定需要水平静止约 20 秒，本次**不在每次启动自动执行**，也不自动
改标度因素、恢复出厂或切换波特率；这些操作应通过厂商工具按手册单独完成。
因此无需每次开机等待旧 SPI 的 2048 点零偏采集。

## 编译、烧录与首次检查

选择原有对应配置编译，烧录对应 ELF；没有新增运行模式：

```powershell
cmake --preset MotionDebug
cmake --build --preset MotionDebug
# 烧录 build/MotionDebug/WWW.elf
```

NormalRun 对应 `build/NormalRun/WWW.elf`，Gamepad 对应 `build/Gamepad/WWW.elf`。
不要用上一次构建目录中的旧 ELF 混淆新旧驱动。仓库原有构建备份钩子不变；
本次验证使用 `APP_AUTO_BACKUP=OFF` 防止把用户其它未提交改动一起自动提交。

先不让车自动运动，通过程序器串口 USART1 发送（每条发送换行）：

```text
IMU
GYRO
```

预期 `ALG=UART_YAW_UNWRAP`、`READY=1`，新增 `IMU_UART` 行显示
`USART=2 TX=PD5 RX=PD6 BAUD=115200`；稳定后 `PERIOD_MS=5 CFG=5`。
CFG=0 为观察，1/2/3 为设置过程，4 为复核，5 完成，6 配置失败。
新模块没有 SPI WHO_AM_I，`ID=0` 是未提供，不表示读 ID 失败；
旧加速度、温度、FIFO/零偏字段不作为新模块的测量结果。

先静止观察，再手动转车：按既有车体约定，从上往下看顺时针转动，
GYRO 累计角和 IMU Z 角速度应同为正，逆时针同为负。方向一致后再架空进行短角度测试：

```text
TURN 60 30
```

等到 FINAL 再发下一条，先核对物理转角和回执方向，再验证 180/360 度。
本次没有自动连接串口、烧录或驱动车辆。
