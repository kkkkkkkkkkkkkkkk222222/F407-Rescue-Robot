# 8113694配套：关闭自动地图边界恢复与mode48预备点复审

基线F407 b618701；本次已fetch并阅读上位机最新 `codex/gamepad-teleop@8113694`。
只修改F407，未修改上位机仓库、LCD、调试输出或新增测试。本轮不烧录。

## 一、自动地图边界恢复已关闭

Task_Process不再调用task_check_boundary_guard。保留函数、mode41编号、HOLD-only及原恢复处理，不改地图尺寸、原点或50/400 mm阈值。
这是关闭自动入口，不是再次调整触发距离：即使内部Location判断出界，也不会由该入口自动张爪/掉头。
夹内300 mm、扫障找回200 mm、ENTER650 mm、末段330 mm/s/1500 ms、通信与APP视觉500 ms、动作本身的行程控制保持。
关闭地图保护后，这些局部里程预算不等于场地防越界保护；错误的新鲜H/D或定位漂移仍可能把车带出安全范围。

## 二、新增mode48流程

`STAGE NAV→mode10+DISTANCE_DONE+闭爪→CARGO_AUDIT占位请求→mode48→140°稳定→三帧复审`

### 进入

仅正式STAGE导航已经完成、闭爪、同task且新action的CARGO_AUDIT可进入；INITIAL_STASH/藏堆不进入。
请求要求vision_frame=0，左右类别/数量和总数为空，非STABLE，无INITIAL_STASH/SWEEP_PICKUP。
核对发现8113694用 `_audit_payload(CargoAudit())`生成请求，因此audit_id可能沿用旧值，伤员任务还可带DESTINATION_INJURY。固件允许这些元数据，不要求把整份载荷误认为全零；它们绝不计入空爪证据。
进入后停车、保持闭爪、相机140°、清READY/VALID和旧审核计数；等现有500 ms相机稳定时间后才置CLAW_VISIBLE，并建立新的审核帧下限。

### 审核

- 将48加入task_audit_state及独立CARGO_AUDIT接收分支。
- 只有140°就绪后的真实新vision_frame/audit_id才累计，重复画面/占位0帧不计数。
- READY/VALID继续使用现有三帧正式规则：首件1 GREEN；之后普通/核心共1～2；伤员单独1件；混装非法。
- mode48不慢爬、不自动GRAB、不使用mode23出口、不因等待时间长放行。
- READY=1但非法或空爪时仍留48，等待上位机释放决定，不把占位请求当空爪立即张开。

### 合法出口

1. 目的地未变：READY+VALID+闭爪后接受定位ALIGN，恢复相机120°，沿原稳定时间和对正逻辑到mode11，再二次视觉ALIGN/走廊/ENTER。
2. 目的地改变：接受合法STAGE NAV，沿实时H/D改道，抵达新预备点后再次请求48。
3. 固件保存本次预备点所属目的地，实际审核改变目的地时拒绝直接ALIGN，防止在错误半区直接投送；但不拒绝新类别的合法审核，也不套用扫障原物资找回的“目的地不可变”限制。
4. 旧的STAGE NAV直接定位ALIGN入口已改为48审核出口；不能绕过48。

### 非法/空爪出口

- READY+非法接受RELEASE_LEFT/RIGHT/BOTH，仍检查释放侧有物资。
- 仅在48且审核确已READY时，允许total_count=0的RELEASE_BOTH；未就绪占位不允许。
- 单侧释放→原YIELD→新帧审核→GRAB/抓后复审→运输。
- 双开放弃按原普通抓取失败路径：非第三次已确认失败走24张爪/退300/转90/3；第三次非法走24张爪/退300→47→RETURN→17→中心3。
- 不增加投送次数，不修改first_delivery_done、藏堆完成或进攻/防守配置。
- 42～46原扫障、40重新ALIGN、无障碍ENTER保持；mode15的1秒投送观察及超时TASK_COMPLETE策略不变。

## 三、最新上位机已修复的旧问题

8113694的 `_output_for_cycle` 已先处理24/3/41/46/47等恢复观察，再处理context_pending，并维护已接受上下文；HOLD/PAUSE使用回执归属。
C++状态解析器已在噪声及异常帧头时清待配对上下文。此前报告中的这两类旧问题不能继续算作未修复。

## 四、仍存在的流程/通信风险

### 1. 分离次数的统计口径在换侧时可能不同

上位机 `_count_separation_acceptance` 每次接受后累加disperse_attempts；F407 `task_prepare_separation`在第三次失败之前允许换保留侧并重置该侧次数。
同一侧连续重试可对齐，但换侧后上位机可能已认定第三次，而F407尚未达到同侧第三次；双开放弃可能走24→3而非期望的47返中。
建议双方统一“同目标总次数”与“同侧松角次数”的定义，或上位机保持同侧重试且以实际47/3分流。此次按要求保留既有三次分离规则，没有顺带改计数策略。

### 2. 非恢复状态的被拒请求仍可能无限重发

新版context_pending已解决已知恢复状态的交接，但对错误目的地ALIGN、未完成STAGE时提前CARGO_AUDIT、错误action/task或mode48误发GRAB等请求，固件必须拒绝，不能覆盖已接受上下文。
上位机等待门仍可能一直重发该请求，表现为停车等待。正常8113694路径按条件生成请求可避免；建议增加针对mode10/48的拒绝推断与重新审核/改道分支，不以放宽下位机审核或新增整场ABORT来掩盖。

### 3. 稳定合法需要一致的真实视觉结果

mode48没有“超时合法”。遮挡、类别在伤员/普通间抖动、完整ROI不断变化时，READY可能长期为0；这属于预期观察等待，不应按“车不动”触发运动恢复。
目的地标志变化还会改变上位机audit action key，导致新action重新累计；应稳定分类而不是重用旧frame编号强行凑三帧。
相机角度及CLAW_VISIBLE是指令角度+时间等待，不是舵机位置反馈，机械未到位仍需现场排查。

### 4. 关闭自动边界入口后不能依赖mode41兜底

上下位机定位源不同的问题仍在。上位机发出的错误但持续更新的H/D不会因“通信新鲜”而自动纠正；局部300/200/650 mm限制也不是全场边界限制。
需要在上位机路径规划/地图合法性判断中保证目标及路径安全，并保留人工停止能力。本次按请求不另加自动边界规则。

### 5. 完成的语义仍要区分

ACK/action_status bit0是接受；mode48 READY是审核收齐，VALID才是合法；mode11是ALIGN完成；mode15是投送观察阶段。
1秒视觉超时TASK_COMPLETE仍按既定策略推进本趟计次和首件标志，它不是视觉确认成功。mode48绝不采用这个策略。
