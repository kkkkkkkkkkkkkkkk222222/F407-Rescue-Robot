上位机T265航向与F407原始IMU航向不是同一个角度量。日志明确标注来源、正方向、参考原点及是否取模，不直接比较两个绝对数值，也不要强行用比例系数使其相等。

## 3. 必须核查：轮式参考轨迹的完整坐标变换

位置：localization/src/fusion.cpp、t265_map/src/t265_map_builder.cpp、localization/include/config.hpp、配置模板及runtime生成路径。

下位机当前物理约定：M1右前、M2左前、M3后轮，轮径70mm，1061.268计数/轮圈，各原始编码器符号为-1。
令m1/m2/m3为原始计数已经乘编码器符号并转换单位后的轮位移，下位机计算：

```text
forward = -(m1 - m2) / sqrt(3)
left    =  (m1 + m2 - 2*m3) / 3
```

当前上位机fusion.cpp仍先算正号forward，再施加encoder_to_robot_yaw_deg。79d7dc1将正式默认改成180度，这会同时翻转forward和left，不等同于下位机只翻转forward。t265_map_builder还有独立公式，不能遗漏。

执行方法：
- 按实际执行顺序列出原始计数、每轮符号、运动分解、附加旋转、场地投影的完整变换。
- 对齐最终物理forward/left，不只机械替换一个负号。若采用上述新基础公式，移除仅为旧符号错误增加的180度补偿；保留真正有实测依据的安装修正。
- 若改用显式前进轴极性参数，各计算链路共用其定义，默认与F407一致，避免重复翻转。
- 先验证轮式参考与F407在前进、左移两种独立动作上的符号。现有180度配置被文档称为实测结果，若与当前代码推导冲突，应记录差异并用对应固件复核，而不是调整T265去迎合。
- 如果以后启用轮式场地yaw，应转换为逆时针正，即-(m1+m2+m3)/(3R)；本次不擅自启用。
- 0x15仍传原始累计计数，不能修改线上的计数定义或重复缩放；历史日志保留原参数。

## 4. 必须核查：MotionDebug命令符号与完成判定

位置：localization/tools/t265_f407_motion_map.py、f407_motion_protocol.py。

- 当前下位机MOVE_BODY参数已经表示前进/左移，Motor_MoveAngle内部完成左移转换。检查地图DEBUG_COMMAND_LEFT_SIGN=-1，按当前固件接口应去除额外反号；前进保持+1。
- 场地逆时针角度到F407驱动角度仍需-1，保留正确的TURN转换。不要把原始驱动正角与UI左转混为一谈。
- 修改debug编码器180度补偿时遵循上一节，不与命令符号混为一体。
- 不将调试地图专用符号再次套在正式比赛H/D或Gamepad命令上；F407在各模式边界已有转换。
- 转角速度字段仍是0.1度/秒，界面若使用轮缘mm/s，只在协议边界按130mm半径转换一次。
- MOVE范围50至700mm/s；TURN有10秒下位机超时，低角速度大角度动作应提示可能超时，不静默放宽固件限制。
- 等匹配命令SEQ、命令类型和本次发送后的新鲜状态确认DONE。收到FAULT/STOPPED或失联，不继续自动执行返航下一段。
- NormalRun与MotionDebug基础极性相同，但转角速度规划不同，不能宣称算法完全一致。

## 5. 橙色伤员后退复核：已有主流程，核查完整衔接

橙色为injured_orange，不是core_black。正常路径：

```text
闭爪 -> mode23首次合法审核 -> mode49半闭爪后退
     -> mode23第二轮审核 -> mode50闭爪 -> mode22运输交接
```

- 下位机左右爪各放松5度，以150mm/s保持航向后退，有效驱动时间累计2秒；上位机不得再叠加YIELD或MOVE后退。
- mode49撤销第一轮pending和稳定证据，保留正确伤员目的地角色，发送非STABLE、frame=0的占位审核。
- 返回mode23后建立新frame floor，等待相机稳定并用新采集图像重做三帧审核。
- mode50保留第二轮已接受的合法pending，不因闭爪遮挡重新审核或判空，不重新启动闭爪。
- mode22必须新鲜、匹配上下文、闭爪且READY/VALID齐全才允许运输。
- 复核非法或空爪沿实际恢复状态处理，不能仍按旧selected_batch运输。
- 扫障取回有独立路径，不将所有橙色审核无条件插入mode49。
- 黑色CORE另有下位机闭爪前50mm推进，上位机不得重复补发；等待实际机械状态和抓后审核。

## 6. 分离候选与运输合法性必须分开

重点：competition_rescue/state_machine.py的_start_disperse()。

- 当前首件完成后eligible判断未包含mixed_material，可能使包含可保留物资的混合侧过早放弃。
- 分别定义“允许尝试分离的候选侧”和“可以直接运输的单件载荷”，不能复用同一合法性判断。
- 候选侧必须有完整视觉证据支持、侧别可靠、满足当前任务和危险物处理规则；不能仅因count>0或mixed_material就放行。
- 线上MIXED_MATERIAL仍是独立类别，不能把未传输的细分组成伪造到审核签名里。
- 未知或危险物不能因此进入正式运输；首件绿色与正式单件规则不变。

## 7. 数量分档夹紧：下位机决定机械角度

- 三帧均能确认保留侧单件且合格：额外夹紧20度。
- 多件或不能证明单侧单件合格：额外夹紧10度。
- 同侧同档再次分离逐次放松5度，即20/15/10或10/5/0度；0度是标准闭爪，不是张开。
- 换侧或换档重新选择夹紧档，但不清零总次数。不能从上位机自己的同侧计数直接断言下位机实际夹紧角度。
- 真实侧计数、总数、类别及危险/未知/混合标志不能为触发强夹而改写。
- 整体审核允许左右交换，不等于保留侧稳定；上位机独立稳定侧别，在动作被接受后锁定。
- 单侧既有合格物又有多余物时不能简单归成“单侧单件合格”。线上无法完整表达的组成，仍须保留保守证据和危险处理。

## 8. 弧线后退与三次失败恢复

下位机当前弧线参数仅用于理解和更新文档，不要求上位机发送这些速度：
- 前段后退最高300mm/s、侧移180mm/s、旋转轮缘切向100mm/s。
- 三轮目标转角12/16/20度；前段路径上限100/130/160mm，路径上限优先。
- 后段平滑撤掉侧移与转向，保持当时航向，后拉最高500mm/s。
- DISPERSE总路径最多300mm；横向预算60mm并预留5mm制动余量，允许提前结束后复核。

上位机要求：
- 使用现有DISPERSE或RELEASE->YIELD，不新增独立侧移、不额外转向，也不因未退满300mm再次补退。
- 等mode35/mode30及相机准备好后，使用动作后的新帧审核，不用固定时间推测完成。
- 动作接受才计数；RELEASE及后续YIELD合计一轮。重发、观察转向、首件轻撞不能误计为选择性分离轮次。
- 新action_id、换侧、档位变化或同一堆新task_id不能绕过三次上限。
- 第三轮结束先审核；合法则抓取运输，真实非法才放弃，不是一到第三次就立即丢弃。
- 第三次非法恢复：张爪->后退300mm->标准闭爪->mode47->RETURN_CENTER->中心开爪->mode3重新寻找。
- mode47可能GRIPPER_CLOSED=true，但AUDIT_VALID=false，是恢复收拢，不是合法载荷。
- 清除旧目标、载荷和pending后再返中心。等下位机新鲜mode3和新视觉帧，不仅凭地图D=0开始抓取。
- PAUSE保持当前动作阶段与上下文；恢复原动作，不重新起动整轮或清零次数。

## 9. 已有审核/扫障机制：保留并复核，不能重写回旧逻辑

- 按图像采集时间独立形成三帧，间隔至少100ms、跨度至少200ms，先发STABLE再等READY/VALID。
- F407本地三个不同audit_id也须满足100ms间隔；重复帧/旧STABLE不能累计或续期。
- 非法签名按实际线上总数、去STABLE标志、0至6类别直方图及零数量非NONE类别掩码比较；忽略左右交换和track ID。
- INITIAL_STASH真实非空可混合、多件、重叠；缺图、黑图、过曝不是非空证据。
- mode43真实审核带SWEEP_PICKUP；mode45及扫障后mode23保持原目的地，伤员保留DESTINATION_INJURY。
- context_pending期间审核阶段仍处理新帧及匹配的拒绝；拒绝需核对新鲜状态、task_id和rejected_action_id。
- 退回42/44后恢复APP/HOLD找目标，不无限重发旧CARGO_AUDIT，不重启已接受的机械动作。
- mode50保持第二轮pending；mode22/40缺pending记录missing_committed_audit，不能从selected_batch猜测。
- 保留mode48预备点运输复核、下位机15秒审核兜底、上位机17秒异常握手时限，区分人工PAUSE。
- 保留单件、首件绿色、投送计数、投送超时与TASK_COMPLETE。

## 10. FIFO IMU与锁存故障适配

- F407 4071c71改用FIFO陀螺仪样本及时间戳逐帧积分，三个模式共用，不改0x15/0x19/0x1A或比赛配对协议。
- FIFO溢出、异常时间间隔、过大积压或读取失败会使IMU无效；不是等待几秒就一定自动恢复。
- 当前stm.fault分支停发指令是正确的，但“等待下位机自动恢复”提示不足：应明确显示锁存故障、人工排查和重新初始化要求，保留任务现场但禁止自动继续。
- NormalRun故障码5不能唯一定位FIFO溢出；细分原因须查看诊断日志。恢复后重新确认下位机状态、配置、任务上下文，不能直接恢复旧运输。
- 程序器文本串口IMU命令输出ALG=FIFO_TS_TRAPZ；IMU_FIFO包含PEAK、OVERRUN、FAULTS、MAX_POLL_MS、TEMP_MC。解析器按字段名兼容新旧格式。
- DT_US现在表示相邻硬件样本间隔，MAX_POLL_MS表示主循环读取间隔，两者不要混淆。
- 这些细分字段不在0x1A中；不能虚构二进制解析。CIRCLES/CAL也是程序器文本命令，不是新增0x19指令。
- 不用地面自动TURN的最终偏差直接标定IMU比例，先区分物理朝向、原始积分、T265航向和停车后残余转动。
