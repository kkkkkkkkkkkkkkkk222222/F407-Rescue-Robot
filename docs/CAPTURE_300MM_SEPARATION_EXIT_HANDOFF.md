# 300 mm限推、三次分离、抬爪退出：下位机修改与上位机建议

基线F407 4699cb8；本次fetch后上位机最新仍为 `codex/gamepad-teleop@b0f954f`。

后续定向修订：**仅第三次复审已收齐且仍非法**改为先张爪、再退300 mm，随后mode47等RETURN返中，mode17到中心后mode3；不再转90°原地搜索。其他本文件描述的退出流程不变。最新上位机请求见`UPPER_THIRD_SEPARATION_RETURN_REQUEST.md`。
本次仅修改F407，未改上位机仓库；不新增UART字段/命令或LCD，不增加/运行测试，不烧录。

## 固件已修改

### 开局抢位

开局前600 mm收爪直退及后续开爪退出/转向，目标速度都设为1000 mm/s，即当前电机接口允许的上限。
保留前600 mm净空要求、原速度控制/轮速饱和及末100 mm的160 mm/s减速。没有把普通抓取/投送速度一并提高，也不是直接输出100% PWM；实际速度受三轮混控、转向和负载影响。

### 夹内推行总预算

普通mode21及聚集mode38的140°夹内慢爬共用同一目标任务的300 mm前进预算。
从第一次进入140°慢爬开始累计；不是限制远距离APP整条接近路线，也不把SEARCH原地扫描算作前进。
APP更新、HOLD、审核action变化、分离后复审不重置；短暂后退不返还额度。分离曲线/20°观察/首绿特殊动作不是普通慢爬，不混入该里程。
到300 mm停车，保持140°审核；若旧APP重新进入靠近阶段，已用完的预算仍阻止继续前进，并转回140°审核。
合法READY/VALID等待GRAB，不自动抓。GRAB被接受后结束这轮抓前限推，核心物资既有50 mm合爪前推进保持。

停止条件还包括收齐审核或分离后复审。若3个真实结果已确认无合格物资，或第三次分离后仍非法，立即进入失败退出。
有候选但尚不能合法抓取时，给上位机4秒选择分离方案；未形成合法抓取/有效分离动作则退出。没收齐审核时也只能在限推后停车等有限观察，不能靠空审核恢复推行。
INITIAL_STASH仍优先按任意非空判断合法，不把危险/超量藏堆误当正式非法物资。真实空爪或没有方案的开局重试仍可退出再选目标，不置first_delivery_done。
300 mm为本地编码器控制预算，20 ms采样和机械惯性会带来少量误差，不是毫米级外部位置保证。

### 失败退出（普通抓取）

mode24内：停车 → 双爪全开完成 → 按当前航向后退300 mm → 左转90° → mode3。
90°方向集中在APP_CAPTURE_ESCAPE_TURN_DEG，默认正向左转；S3回120°。后退使用单次锁存的里程原点，PAUSE后恢复剩余行程。
本轮任务标记取消，旧APP、旧GRAB、旧NAV不能拉回；HOLD只ACK，不打断倒退/转向。完成后上位机用新task_id选新目标。
在普通非法抓取审核中，RELEASE_BOTH视为“明确放弃”：接受后直接进入上述mode24退出，而不是只停在mode34。
**例外不变**：INITIAL_STASH/route_to_stash仍双开→34→RETURN；mode45仍走原扫障失败→46；扫障取回mode23复审的原释放路径不改。
原聚集360°的mode24停车+HOLD握手仍保持，未改成这条物理退让路径。边界恢复、显式PAUSE/ABORT及已有电机/位姿故障路径仍可优先中断动作。

### 三次递进分离

只对新接受的带侧DISPERSE或RELEASE_LEFT/RIGHT计次，重复帧/相同action不计。每次之后必须重新做真实三帧审核；不是看到转动完成就判失败。
同一保留侧锁存第一次夹持基准，第二次在其上向张开方向松10°，第三次松20°；中途换动作类型也不改变本轮基准。

| 第一种分离动作 | 第一次保留左/右 | 第二次保留左/右 | 第三次保留左/右 |
| --- | --- | --- | --- |
| 带侧DISPERSE，15°夹持基准 | S4=61 / S2=119 | 71 / 109 | 81 / 99 |
| 普通单侧释放，25°夹持基准 | S4=51 / S2=129 | 61 / 119 | 71 / 109 |

这里只调整保留侧，释放侧仍全开；Touch仍S4=76/S2=104。第三次曲线保留侧可能比Touch还松5°，存在物资滑落风险，必须复审。
换保留侧或真正的新task目标重置该侧计数；20°无侧观察与一次性首绿bump不计入这三次。
下位机不从总数猜测保留侧，“有合格且容易分离”仍由上位机基于完整ROI、类别/侧别作判断。

### 放置区对正及抬爪退出

SAFE_ALIGN进入容差1.5°→3°，保持容差4°→6°；像素修正仍保留一次且上限±15°，聚集/普通抓取像素对正阈值不改。
正式投送完成后mode16改为：S1升降到开局55°、等待1秒 → 保持抬起后退300 mm → 停车、S1回行驶85°、等待1秒 → mode17返中。
S3维持120°，取消上一版“90°抬相机1秒”的动作；本次抬的是S1爪子机构，不是相机。升降没有位置反馈，1秒是可调的机械等待，不是传感器证实到位。
提前RETURN只缓存/ACK，不能提前转向、放下或重置退出距离。1秒投送观察、650 mm ENTER、330 mm/s末段、1500 ms接触保护均不变。

## 上位机必须配套的修改建议（可直接转交）

1. **修复上下文等待门。** 在 `_output_for_cycle` 的context_pending拦截之前处理新鲜24/3/46等恢复状态。不能因待发GRAB/RELEASE未被接受，就永远重发它并阻止恢复；HOLD/PAUSE使用当前已接受task/action，不用待接受编号。
2. **mode21/38/37允许停车审核。** 不要因底盘不再前进就当作卡死、再发APP重置接近；继续消费完整夹爪ROI，生成真实新vision_frame和audit_id，READY之前不分离。合法发GRAB；数量超限且有可保留侧才分离；没有合格物资/侧别不可靠时允许无侧20°观察，仍无方案则发RELEASE_BOTH放弃或HOLD等待下位机有限观察退出。
3. **放弃路径接受24→3，不只等34。** 普通非法抓取中的RELEASE_BOTH会执行张爪、后退、转向，mode24可以持续数秒；持续同归属HOLD，不能另发APP/GRAB/NAV取消。INITIAL_STASH的RELEASE_BOTH仍等34，不能把两种业务混为一谈。看见3后清旧track、建立新frame floor，用新task_id选目标。
4. **把 `CompetitionSettings.disperse_limit=2` 改为3并复核全部重试分支。** 现在b0f954f最多两次，无法主动用到第三次松20°。每次必须动作完成→新三帧审核→仍非法才申请下一次；新物理尝试分配新action_id，重复帧沿用原action_id。换track不等于新物资堆，不能靠新task_id清除已消耗预算；换侧次数也应有上位机整体上限，防止左右交替无限重试。
5. **对齐容差只改放置区。** 本地方位预检若还硬卡1.5°，应与F407的3°进入/6°保持一致；仍以对应ALIGN上下文的新鲜mode11为交接，不放宽聚集抓取像素阈值或在未完成ALIGN时ENTER。
6. **mode16完整等待S1退区动作。** 连续发送RETURN H/D供缓存，但允许升降各1秒静止，不能把它作为卡住而触发ESCAPE；等mode17才按返中运动判断进度。无需新增相机抬起命令、UART字段或把S3角度当S1高度反馈。
7. **任务规则保持。** 恢复不修改first_common_delivered、initial_stash_done或投送次数；首件只运单绿色，后续普通/核心最多2件、伤员单件。松爪后的审核须包含全部ROI，不能只数目标或把实际3/4件截断。
