# 上位机陀螺仪遥测适配说明

本次只新增下位机到上位机的遥测，不修改运动PID、陀螺仪解算、舵机或比赛流程。
核对的上位机版本：`danmo-teng/shijue_fangan` 的 `codex/gamepad-teleop@f55bc83`。
该版本尚未提供这里定义的 `0x1F` 解析，需要上位机配套增加。

## 接口与频率

- 新板：UART4，JP506，主控TX=PC10、RX=PC11，115200 8N1，串口交叉连接并共地。
- `0x15`：原有三轮原始累计计数低16位保持不变，正常约100Hz。
- `0x1F`：新增陀螺仪帧，正常约50Hz。各模式共用Robot/Vision发送路径。
- 传感器仍以230400bps、1kHz接入UART5；上位机遥测50Hz不改变传感器采样率。
- 所有发送均为非阻塞队列；ACK和任务状态优先，队列满时可替换未发送的遥测。
  频率不是硬实时保证；拥堵时以最新数据为准，禁止要求每个SEQ都必须到达。

## 0x1F格式

沿用15字节帧：`A3 B3 TYPE SEQ P0 P1 P2 P3 P4 P5 P6 P7 CRC_LO CRC_HI C3`。
TYPE为`0x1F`，SEQ是本类型独立的uint8计数，按256回绕。
CRC16/MODBUS初值0xFFFF、多项式0xA001，覆盖TYPE到P7这10字节，CRC低字节先发。

| 字段 | 类型及单位 | 含义 |
| --- | --- | --- |
| P0..P3 | int32，大端，0.001度 | 累计yaw，可为负数，可超过一圈；除1000得到度 |
| P4..P5 | int16，大端，0.1度/秒 | Z轴角速度；除10得到度/秒 |
| P6 | uint8，毫秒 | 打包时角度/角速度数据年龄的较大值，超过255饱和为255 |
| P7 | uint8位标志 | 见下表；bit7保留为0 |

| 位 | 名称 | 含义 |
| --- | --- | --- |
| bit0 / 0x01 | VALID | 当前数据可使用 |
| bit1 / 0x02 | READY | 传感器就绪 |
| bit2 / 0x04 | RECOVERING | 传感器通信正在恢复 |
| bit3 / 0x08 | UNCERTAIN | 航向参考被判为不确定 |
| bit4 / 0x10 | STALE | 角度或角速度年龄达到150ms，或尚无角度样本 |
| bit5 / 0x20 | YAW_CLAMPED | yaw超出int32范围后被截限 |
| bit6 / 0x40 | RATE_CLAMPED | 角速度超出int16线格式范围后被截限 |

正常P7为`0x03`。只有READY且没有恢复、不确定、过期或截限标志时才置VALID。
传感器异常时仍继续发送携带无效标志的帧，不能把缓存角度误当成新有效数据。
角速度按0.1度/秒编码，向零取整；不表示传感器本身只有0.1度/秒分辨率。

## 方向与参考

本车单轴陀螺仪逆时针增大、顺时针减小，yaw和角速度直接沿用下位机IMU数据方向。
不要套用电机的`APP_MOTOR_HEADING_OUTPUT_SIGN=-1`再次反号。
调试TURN正角度对应本车顺时针运动，不能据此把陀螺仪正方向也定义成顺时针。

yaw是启动/明确归零后的本地累计角度，不是磁北航向，也不是已对齐场地的绝对航向。
主控重启、显式IMU归零或重新建立定位参考后，上位机需要重新建立航向偏置。
不要把累计yaw直接覆盖到T265场地坐标系航向；需先完成参考对齐。

## 给上位机Codex的修改要求

1. 在串口解析器中加入`0x1F`。大端有符号解析，保留原`0x15`、任务上下文配对、
   `0x19/0x1A`调试、投送计数及视觉审核流程。无效帧仍记录状态，但不进入航向融合。
2. 更新所有实际使用的串口接收/转发路径，包括localization、t265_map、手柄串口代理
   和比赛程序的类型白名单。不要只改界面，而使真正的串口拥有者把0x1F丢掉。
3. 显示并记录yaw_deg、yaw_rate_deg_s、age_ms、status、SEQ和本机单调接收时间。
   单独统计IMU序号与新鲜度，不把它和编码器或任务状态的SEQ混算。
4. 若用于定位，先对齐场地航向参考，再使用有效角度的变化量更新航向；角速度用于
   短时预测。不要对模块已经给出的角度再积分一次，也不要重复累计角度和角速度。
5. 上位机需叠加自身接收超时判断。P6仅表示打包时的数据年龄，不能替代传输后新鲜度。
   接收无效/过期数据时沿用既有可恢复处理，不因新增遥测自动引入永久故障锁存。
6. 保持现有T265外参、坐标约定和比赛状态机。此说明不要求新增测试程序。

本仓库`tools/vision_protocol.py`提供`imu_frame()`与`parse_imu()`作为参考。
示例：SEQ=7、yaw=-720123毫度、角速度=-1200个0.1度/秒单位、age=1、status=3：

`A3 B3 1F 07 FF F5 03 05 FB 50 01 03 31 0E C3`

## 下位机核对方法

NormalDebug程序器串口发送`PING`，UART4行新增`ODOM_TX`与`IMU_TX`。
它们统计UART发送完成回调，正常每秒分别增加约100与50。
这只能证明主控UART已完成发送，不能证明RDK收到或解析成功。
不需要启动底盘运动。COM18文本调试不承载这里的0x1F二进制数据。

编译核对：NormalDebug、NormalDebugTask、旧板MotionDebug通过。
原有协议检查23项通过；正负角度、多圈、整数上下界及CRC参考往返检查通过。
实际烧录与发送计数以程序器连接恢复后的实机记录为准，不能用编译成功代替。
