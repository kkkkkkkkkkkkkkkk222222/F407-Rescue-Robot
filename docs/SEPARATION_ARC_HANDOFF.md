# 数量分档夹紧与弧线分离：上位机交接

下位机本次在 b0d8875 基础上修改；最终版本以本文件所在提交为准。
已读取上位机 codex/gamepad-teleop@ff6fe77，未修改上位机仓库。

## 下位机执行规则

- 保留侧三帧都明确为单件、类别符合当前首件/目的地要求：额外夹紧20°，同侧同档失败后依次15°、10°。
- 多件或无法证明单侧单件合格：额外夹紧10°，同侧同档失败后依次5°、0°。0°是标准闭爪，不是张开。
- 每轮锁定侧别和夹紧角度；改变侧别或从多件变单件，只重选夹紧档，不清零总次数。单侧释放加后续YIELD是一轮，重复串口包不增加次数。
- 最多三轮。正常单件合法则结束分离，走原闭爪、抓后审核及运输流程。
- mode37支持继续接收新审核和证据过期撤销；开始分离还会复核三帧、STABLE和500ms有效期。

## 弧线

恢复旧弧线的左右方向：保留左侧时向右侧展开并右转，保留右侧时镜像。
前段后退最高300mm/s、侧移最高180mm/s、旋转轮缘切向最高100mm/s。
三轮相对转角目标12°/16°/20°，前段路径上限100/130/160mm。
路径上限优先，不能为了追满转角继续绕行。

前段结束后平滑收掉侧移和转向，锁定当时航向，最高500mm/s继续后退。
DISPERSE总路径仍最多300mm，YIELD沿用原请求距离。取消独立20mm侧移，不叠加额外平移。
每轮横向空间预算60mm，预留5mm制动余量；达到内侧阈值就提前结束运动并复核，不要求每次退满300mm。
靠近横向边界时，已经转角后的纯后退也会减速，因为它在初始坐标系仍有横向分量。
这些阈值是首轮实车试调值，不是保证实际无滑动、无惯性超量的物理限位。

## 上位机应保留与适配

1. 保留按图像采集时间先完成三帧稳定、发送STABLE后等当前上下文READY/VALID的顺序。真实数量和类别不能为获得20°夹紧而改写。
2. 审核按整体类别直方图稳定，不等于物理左/右侧稳定。下位机强夹还要求采样期间该侧一直为单件合格；若左右分配抖动，会保守选择10°。上位机继续稳定保留侧选择，不要在同一机械动作中切换侧别。
3. 一个侧别线上只有一个类别，完整“一绿一红”组成不能直接传到F407。上位机应继续依据完整检测结果选择保留侧，发送真实侧计数、混合/危险/未知标志及SIDE_VALID/TARGET_RIGHT。下位机给稳定混合多件留下有期限的决策窗口，但不会因此认定载荷合法。
4. 使用原DISPERSE和RELEASE→YIELD即可，不新增横移命令，不按重发次数计数，不更换action_id来重启动作。等mode35/mode30完成，再用新鲜画面复核。源程序里的3次上限不能靠切换侧别、档位或同一堆的新任务编号绕过。
5. 第三轮仍失败：下位机张爪、后退300mm、标准闭爪后进入mode47。这里GRIPPER_CLOSED可能为真，但AUDIT_VALID为假，是恢复收拢，不是成功载荷。不能猜测selected_batch或切到投送。
6. 上位机mode47处理继续清除旧目标、pending审核和载荷上下文，并发送原RETURN_CENTER。ff6fe77的mode47分支和RETURN等待新鲜mode3的基本逻辑已经符合，不要改成仅检查闭爪标志。
7. 下位机到中心后先开爪，再上报mode3和RETURN完成。上位机等mode3后按原相机准备和新帧门槛重新寻找，不要仅按地图D=0提前开始抓取。
8. PAUSE保留当前弧线阶段、原点与次数，恢复原动作；协议异常、STOP/ABORT及三轮失败仍走原兜底。伤员23→49→23→50→22、mode48、单件/首件规则、投送计数和TASK_COMPLETE不变。

本次无需更改串口配对协议、0x15/0x19/0x1A、T265外参、定位模式或PID。
上位机修改建议不要求新增测试程序；只做与当前分离流程相关的增量适配。

## 实车确认重点

先看单侧两件是否用10°、单侧一件合格是否用20°，再看弧线是否让释放侧和中间物块退出。
关注每轮结束后是否减少了多余物块，以及第三轮失败后能否完成闭爪返中心和重新开爪。
如果爪形形成倒扣、夹住底边或真实检测数量错误，单靠轨迹不能保证分离，应保留释放重抓出口。
