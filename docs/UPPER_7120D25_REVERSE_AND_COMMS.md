# 7120d25 配套：分段倒退、650 mm推进及通信检查

基线：F407 af8c534；上位机 `codex/gamepad-teleop@7120d25`（本次获取时的最新分支）。
上位机较4115aea只增加扫障观测日志和修复说明，未改变任务状态机、命令编码或握手。
本次不改上位机，不新增超时/FAULT/ABORT，不新增上位机后退命令，不运行回归测试、不烧录。

## 回退修复

三条入口 `VS_BACK_OBSTACLE / VS_BACK_LOAD / VS_FAILED_BACK` 共用修复：

`SELECT → ALIGN（必要时）→ DRIVE → DONE → 下一段；全部消费后恢复H并继续原流程`

- 进入物理回退阶段时冻结轨迹和末端位置；CLEAR/HOLD只有ACK，不能重置回退对象。
- SELECT逆序归并同方向、近共线点（横向偏差8 mm、航向偏差8°）；不跨越大转向或反向运动。邻近纯转向点按同一旋转方向合并，保留真实转向。
- 一次锁存段起点/终点、长度、单位方向和航向。atan2仅在选择非零长度段时计算。
- ALIGN只调用现有Motor_TurnAngle并等完成，误差≤5°可跳过；DRIVE只调用Motor_Move，绝不启动离散转向。
- DRIVE使用锁存航向、沿段剩余量减速和有界横向修正；用终点前容差/越过终点截面结合横向误差结束，不翻转180°追旧点。
- 中间段纵向容差10 mm、横向20 mm；最终S沿用30 mm容差。完成立即锁存DONE并停止一次，消费索引只能向起点减少，位置抖动不能复活旧段。
- 原物资200 mm预算、44/45审核、46失败返中和最终恢复H的动作不变。

LCD保留 `CMD:SWEEP OK`（表示ACK，不是动作完成），增加BACK_OBS/BACK_LOAD/FAIL_BACK、回退阶段、剩余采样点/总点数、剩余距离、航向误差、横向误差、最近一次转向返回状态。
`P0/1/2/3/4 = SELECT/ALIGN/DRIVE/DONE/FINISHED`。SEG计数是被归并前的采样点数，不是假定每点一个运动段。
TaskStatus还保留段长、目标与当前位置、当前yaw、锁存航向、连续后退指令forward/yaw供调试器读取；转向的轮速由电机闭环内部管理，不冒充为后退指令。
UART 0x17不增加字段，7120d25的上位机扫障日志仍只能观察外部mode及夹爪状态。

## 通信检查：已确认的一致项

15字节帧、TYPE=0x18任务/0x17状态、CRC16-Modbus、SEQ及参数端序匹配；bit6按操作码复用的定义一致。
0x13视觉请求0/±200和旧固定距离/±150一致。正式1～2件、首件1 GREEN、INITIAL_STASH优先非空一致。
42/43取障、44/45找回、46→RETURN→17→3、39→23→40→ALIGN匹配。三帧审核按audit_id而非串口SEQ累计。
PAUSE冻结；HOLD在普通靠近、mode41、mode39、mode44的语义不同，上位机当前按状态使用。

## 潜在隐患与建议（仅诊断，未扩展修改）

### 1. 高优先级：上位机停发与下位机失联保护的假设冲突

上位机 `localization/src/main.cpp` 串口心跳线程在命令文件停止更新250 ms后停止代发；README明确依赖F407看门狗停车。
但F407 `task_mission_valid`仅检查received/VALID，`task_report_valid`不检查帧龄；Task没有调用已有 `Vision_MissionIsFresh`。
因此上位机进程卡死、串口断线、转发线程停止时，最后APP/ENTER或自主扫障可能继续，不能把“停止发包”当作已停车。
这是两边的真实安全假设不一致，不只是文档措辞。应单独约定失联策略及哪些自主阶段允许完成；本次按要求不新增超时或FAULT。

### 2. 中优先级：ACK不是事务编号，也不是动作完成

上位机 `_command_acceptance_seen/_opcode_acceptance_seen` 用relay已发送payload + ACK不同于入口值推断接受；0x17只回显8位SEQ，不含已接受opcode/payload或动作代号。
异步relay/状态快照可能把前一条命令的ACK当成本条证据；100 Hz的SEQ约2.56秒回绕。
当前accepted锁存和后续mode/夹爪/审核条件降低风险，但不能证明ACK严格对应某个物理动作。建议后续统一绑定实际发送SEQ及命令代号；切阶段还要验证新鲜状态/动作结果。

### 3. 中优先级：最新值邮箱会覆盖中间命令

`vision_save_mission`写入单个latest_data.mission，Task每20 ms读快照；relay每10 ms发帧。
同一DMA批次/两个Task周期间的中间命令可能不被Task执行；持续重发普通命令是必要的。单帧PAUSE/ABORT后若立即覆盖成普通命令，不能保证已停车。
上位机FAULT持续ABORT、状态过期持续PAUSE属于正确做法；紧急停止不能依赖一次性帧。建议独立锁存紧急命令或设计其确认，但本次不改变安全命令协议。

### 4. 中优先级：上位机FAULT等待与下位机故障锁存

上位机 `step` 在stm.fault时暂停命令发送并等待恢复；F407硬件/位姿等STOPPED故障保持锁存，只有远程STOP类有重新配置的特定入口。
部分故障不会自行恢复，现场表现可能是双方一直等。应明确人工复位/重新配置流程，不能误以为重发CLEAR能恢复。

### 5. 坐标、进度和状态诊断范围

F407边界与回退使用编码器/IMU积分的Location，上位机导航用T265/融合坐标；不能仅用上位机坐标判断已经回S或触发边界是否合理。
同样，0x17的mode39+ACK+MOTORS_ACTIVE不是实际移动证据，且没有内部轨迹字段。此次LCD/TaskStatus补充诊断；上位机7120d25新增日志只覆盖外部mode变化。

### 6. 投送成功与实际距离不是同一含义

末段1200 ms保护也会置nav_final_push_done，随后进入mode15等待视觉判断。上位机应使用真实投送视觉证据决定TASK_COMPLETE，不能把ACK或mode15视为物块已入区。
上位机预备点仍距入口600 mm，本次650 mm是下位机额外5 cm推入量，并非要求把上位机预备点同步后移5 cm。

### 更正上一轮“状态新鲜度风险”

完整检查发现上位机 `step()` 在各状态分支之前已有 `if not stm.fresh` 统一拦截并发送PAUSE。
因此CLEAR内部没有重复写stm.fresh不构成遗漏；此前仅看局部分支提出的该项风险撤回。
