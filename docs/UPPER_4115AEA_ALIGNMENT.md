# F407 / 上位机 4115aea 对齐说明

基于 F407 c71efd6；已获取并阅读上位机 `codex/gamepad-teleop@4115aea`。
本次只改 F407 仓库，不改上位机。按用户要求不运行回归测试；固件编译结果见交付记录。

原有15字节帧、计数字段和CRC不变。真实3/4件必须保留到总数字段并判非法。

mode45禁止特殊扫障bit6及INITIAL_STASH，目的地必须与CLEAR前保存的正式目的地一致。
mode45合法仍留在45等待GRAB，不能进22；合爪→39倒退→23复审→40。
旧固定距离0x13（P2/P3=80～600，P4/P5=±150）保留；它不是新视觉流程。

## 伤员扫障动作（普通/核心完全镜像）

保存S、H和原物资审核清单：左转90°→前进200→张爪完成→倒退200回S→恢复H；
42/43找障及特殊审核→GRAB→39合爪→沿轨迹倒退S→恢复H；
右转90°→前进200→张爪完成→倒退200回S→转至左侧原物资方向（180°）；
44/45找回→GRAB→39合爪→沿轨迹倒退S→恢复H→23→40→ALIGN。

44无目标/HOLD时沿原暂放航向低速前进，不做普通360°SEARCH。所有找回前进通过同一限额函数。
预算达到200 mm后禁止继续前进，留3.5秒原地观察窗口；找回阶段总时限15秒。
45非法审核3.5秒可回44，但不会重置预算或总时限。期限内合法可GRAB；否则张爪、沿轨迹倒退、恢复H才发46。
46只通过合法RETURN_CENTER进入17；旧CLEAR仅ACK，旧APP/GRAB不启动动作；不要求TASK_COMPLETE、不计投送。
轨迹上限256节点，按10 mm或5°变化采样；容量不足时安全放弃并沿已有轨迹倒退，不能覆盖回程记录。
有限采样、编码器误差、控制周期和机械惯性意味着实车终点有误差；200 mm是本地里程控制预算，不是外部测量保证。

## 仍需上位机/现场注意的协作问题

1. **边界判定坐标不同。** F407 `Location_Update10ms`积分编码器并使用IMU；边界由该内部x/y判定，不直接用收到的上位机融合位姿覆盖。地图坐标不能单独解释mode41。
   触发快照保留在TaskStatus：boundary_x_mm/y_mm/yaw_mdeg/edge_mm/heading_deg/turn_done；LCD在41交替显示坐标、边距、目标航向和完成标志，另显示触发/当前yaw。
2. **mode45上位机不发分离。** `state_machine.py:3360`附近的 `_safe_sweep_pickup_output` 只发布APP/HOLD、审核或GRAB。非法审核不能等待普通释放握手；本固件用有限观察、预算及总超时走46。若额外收到释放/分离命令，找回流程按放弃处理，不进入可能越过预算的普通分离运动。
3. **同类不等于同一件。** 上位机 `safe_sweep_target` 用original_classes筛选、original_ids优先；track重建后仍可能抓到另一件同类物资。F407保存原审核清单并核对正式规则和目的地，但协议没有逐件身份，不能证明取回的是原件。
4. **状态新鲜度风险。** 4115aea在CLEAR分支判断42～46时没有像后面的23交接那样显式加 `stm.fresh`。这是代码层面的风险，是否实际误动作取决于外围过期状态处理；建议上位机统一要求新鲜状态后再切角色/执行失败返中。
5. **传感器/运动故障不是46。** 没有可靠位姿时不能声称已回S；位姿或电机故障保留STOPPED/FAULT安全路径。上位机不能把FAULT当作已完成找回失败倒退。

无障碍直接ENTER、无homography依赖、普通危险释放、20°观察、普通mode24恢复及1000 ms投送确认保持。
