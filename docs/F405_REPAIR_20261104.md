# F405 误停修复：本轮回执与接口增量

本轮独立核对上位机 `582a1f6` 的 CHANGE_WORKFLOW、F405_REPAIR_HANDOFF。
接受已证实竞态修复和精简方向；真实 UART 错误之后如何输出仍需人决定，
不把它与年龄下溢产生的假 RECOVERING 混为一谈。正式比赛遥测先报告缺项，不扩本轮范围。

## 问题、修改、影响

已证：旧 IMU_Update 在取 now 后才关中断，ISR 可以先更新 angle_ms/rate_ms，
使无符号年龄下溢。旧链路会清 ready，Location.valid 变 false，Debug 报 ODOM3，
motor 调 Motor_Stop，Task 也可能转恢复。交接中的 age0～2ms 与这种竞态相符，
但本轮没有原始故障日志或板端回执，不能说已经证明所有异常都来自它。

现移除 UART IMU 的运行时年龄门控，剩余 age 展示在同一临界区用一次 now 获取。
共享 UART 驱动同时作用于 F405 测试/比赛，使用该驱动的旧板也受影响；
未更换 F405 运动学、PID、转角末端控制或比赛业务流程。
删除额外100ms转角/组合运动/CIRCLES样本年龄退出，保留原动作自身结束和超时。

| 输入状态 | 本轮实际行为 |
| --- | --- |
| 首次尚无合法数据 | 不造零测量；原初始化/动作拒绝仍生效；晚到数据仍能初始化 |
| 合法帧 | 保留真实 yaw/rate/计数，递增各自源ID；不因年龄长而清 ready 或结束动作 |
| 校验错误帧 | 丢弃坏帧，沿用最后合法值；源ID不增加，不冒充新测量 |
| 仅因为时间变长/旧竞态 | 不再进入 RECOVERING；原动作身份、进度不会被这一条路径取消 |
| 显式 ORE/FE/NE/PE UART错误 | **本轮保留原处理**：ready=false、RECOVERING；现有控制层仍可能结束动作/停车，3个合法角度帧恢复ready；已结束的动作不自动重放 |
| 持续静默且没有UART错误 | 不新建失联阈值；没有新ID，不补零；当前控制使用最后合法值并受原动作结束/超时约束；连续任务不保证有统一有限超时 |

最后两项的输出取舍已经向用户提出，尚未得到选择。推荐真实错误时暂缓输出、保留原动作后续恢复；
但尚未实施这项行为变更。因此本轮是已证竞态修复，**不宣称所有真实恢复误停已解决**。
长间隔可能丢失整圈信息，现有串口角度展开不能凭空恢复未收到的整圈；不标成已校准。

## 保留的动作时间与删掉的资格检查

- 保留：MOVE 原行程超时、TURN/组合角度原10s动作超时、末端停稳/加减速节拍、
  CIRCLES 原圈间等待和整批动作超时、轮子测试脉冲截止、人工STOP、原Task业务等待和mode51。
  它们仍可能正常结束或超时结束动作，未改阈值，也未作为新的传感器失联探测。
- 保留：串口初始化/配置应答的原等待与重试节拍；发送错误后原100ms重试调度。
- 删除：IMU运行时150ms ready资格、300ms heading_uncertain时间锁存、
  调试转角及组合动作100ms源年龄退出、07的15/50ms资格阈值、08的20ms资格、
  8ms排队过期、100ms TX卡死时间巡检、20ms逐字节请求计时、TIM5寄存器/倒退巡检。
- 删除：后轮逐沿计时、IMU逐字节附加取时、轮/gyro间隔最大值、高频队列/发送年龄统计、
  每帧RAM封印重复计算、F405每次主循环阶段记录及100Hz Motor诊断快照。
  F405 TRACE/DIAG时间打印停用，STAT/IMU/ENC和显式错误计数仍可按需读取。
- 保留：07速度计算的实际区间、整帧gyro源事件、发布调度、nonce/epoch身份、数值与CRC校验；
  不引入新的ISR、计时巡检、协议族或停车条件。

DMA发送仍由主循环唯一启动，使用持久独立缓冲区；活动帧不会被队列覆盖。
显式DMA错误走已有abort及硬件TC排空，检查EN/DMAT/TC是发送所有权约束，不是时间资格。
不再自动按年龄丢包；队列仍有界、同类未发遥测保留最新，因此仍可能有可见源ID跳号。
未进行板上混合流完整性验证，不宣称历史多余头前缀已在本轮得到实机复现或根因确认。

## 接口 v1.2 最小变化

完整字段布局沿用 v1.1 的01/02、03/04、05/06、07/08；本增量与
[JSON](F405_REPAIR_INTERFACE_20261104.json)中的语义优先。封装version仍为1，
identity major/minor=1.2，capabilities=0x3DF（不再宣告统计和质量页）。
09、0B查询返回7F/status2不支持，不返回伪造的零统计。

- 07 VALID 表示本次真实计数区间可计算且无已检测的非法跳变/数值损坏。
  未知时间界、EXTI_PENDING、epoch未知不再自动清VALID；这些已有标志仍保留其描述。
  不按区间超过50ms或参考重建作废原始车体系速度。dt<=0仍不能做除法，速度无效为INT32_MIN。
  无新采样时不发新07，不补造零。前/左为正公式、raw/delta顺序和单位不变。
- 08 VALID 表示存在校验通过、可表示的源值；不与ready/recovering/年龄/未知界绑定。
  yaw/rate各自的源ID、NEW/REPEAT不变，完全无新源则不重复发08。
  时刻改为**ISR完成合法帧校验并更新源值后**的MCU事件，未冒充物理采样时间。
- 0x1F保持15字节布局、CCW正毫度yaw、0.1deg/s rate、饱和age。UART驱动下
  VALID同样表示已有合法可表示值；不因RECOVERING/年龄清除，STALE只表示尚无角度样本。
- clock_flags.bit0仅表示TIM5已配置，bit1表示RNG epoch可用；无健康认证。
  epoch_fault只保留0/1 RNG可用与否，SYNC epoch_valid也仅表示RNG状态。
- FFFFFFFF时间不确定度、SOURCE_TIME_UNBOUNDED仍如实保留，TIME_BOUND_KNOWN不置位。
  RDK需按当前B方向理解“未知”，不再把旧时间证明门槛作为本轮反馈使用前置；
  不能把新语义描述成精度已验证或误差已标定。人工STOP与旧动作配对不变。

## 比赛接口缺项（本轮不实施）

NormalDebugTask没有07/08/身份扩展，仍默认115200；测试Timed为230400。
建议后续让完整Task独立复用UART4测量发送，不启用Debug动作任务，保留
0x16位姿、0x18+0x1D命令、0x17+0x1E状态。原频率07=50Hz、08=100Hz单独需14250B/s，
115200 8N1仅11520B/s；选230400或降发布频率需两端单独确认。不得挤掉任务回执。

## 检查与身份

本轮必要检查：NormalDebugTimed、NormalDebugTask编译；现有UART IMU测试直接改用新语义；
现有遥测模块检查去龄门后的真实区间与CRC；现有发送队列缩到32混合帧核对所有权/显式错误恢复。
详细编译身份与结果见 CURRENT_STATUS。未执行整套动作或精度测试。
COM18只读PING/STAT/IMU尝试未取得回传，串口调用阻塞后终止；没有烧录、复位或运动命令。
板端actual仍仅有交接报告11eeacf/dirty1，不把新仓库HEAD/构建身份冒充实烧身份。
