上位机会话声明提交81879e0；actual_lower_firmware和actual_lower_mode均为unconfirmed，不能据日志证明实机已烧录当前F407提交。
包内5个比赛会话，主要有效动作记录为192310和192752；其余3个最终停在WAIT_START且STM状态不新鲜，不能据此单独判断IMU初始化失败。

## 结论

最有证据的问题是爪内观察质量检查被无关边缘框整体否决，以及已知多类别组合被当成不能选择保留侧。不是物块数量大于1就没有分离代码，也没有足够证据认定摄像头物理角度未达到140度。

## 1. 审核门槛导致的等待

192752会话有两个明确窗口：

| 秒数 | 上位机状态 | 记录 |
|---|---|---|
| 26.334至33.905 | CAPTURE_AUDIT | 约7.57秒无真实cargo_audit_wait/stable事件，随后F407进入mode24恢复 |
| 47.228至54.833 | CAPTURE_AUDIT | 约7.61秒同类等待，未发起选择性分离，随后mode24恢复 |

日志并非没有检测：相应窗口分别记录47和44幅检测结果，存在多个高置信度绿色物资。
按日志内真实ROI与visible track的bbox做几何复核，两个窗口分别47/47和44/44都存在会触发partial_roi否决的框；部分帧还触发truncated。
举例：frame395绿色框[744,168,246,155]约52.9%落入ROI，达到20%的“部分进入”门槛，但不足60%的完整候选门槛，因此会令整个capture_observation_valid=false。
frame727的橙色框[707,79,371,291]约40.9%落入ROI，同样会否决整幅爪内观察。

几何复核使用日志多边形栅格化估算，不是带原图的完整重放；栅格边界有微小差别，但上述数值远离门槛。日志未保存历史STM角度及每帧capture_observation_reason，不能断言每一帧的真实拒绝原因只有这一项。

建议：
- 先确定哪些检测属于实际爪内/爪口占据区域，哪些属于远处背景或画面边缘。不能让任意与ROI有交集的框否决所有可靠爪内目标。
- 部分ROI、裁切否决必须与真实载荷候选相关。对可信爪内候选仍核对类别、数量和完整性；不是只保留selected track、忽略额外物体。
- 重新核对140度下的ROI，尤其上边缘和左右画面边缘。存在几何相交不等于物块实际在爪内。
- 无观察与真实空爪分开；无观察不能伪造为空，也不能伪造合法运输。

## 2. 已经分离一次，但边缘框阻断复核

192310会话：
- 195.955秒进入聚集目标审核。
- 199.928秒明确发起“锁定保留right侧目标，启动选择性分离”。这说明实际分离流程曾成功进入。
- 202.722秒动作后回CAPTURE_AUDIT。
- 206.760秒进入mode24恢复，距离复核开始约4.04秒。

此复核窗口的24幅记录均包含右边缘绿色track223截断框，例如frame3436的[1202,241,77,339]，仅约4.1%落入ROI。
当前上位机对“图像边界截断且ROI交集大于0”直接置整幅观察无效。该框即使不满足爪内候选条件，仍阻断左右两个清楚的绿色目标及后续分离决策。
因此该次“一次分离后退出”的更具体原因是复核无法形成新证据，随后触发等待恢复；不是日志证明两次上限配置没有生效。

建议：先修整幅观察否决的作用范围，再讨论延长等待。只延长4秒会让车等更久；减少帧数也无法修复capture_audit=None。
保留两次实际分离预算。第一次复核可观察且仍有合格候选时再进行第二次，第二次完成真实复核后仍失败才返中心。

## 3. 多个已知物体被合并为unknown，导致只观察转向

192310会话frame4010：visible检测包括绿色track291、橙色track293及边缘危险物track298。
审核事件记录右侧2件、总数2，保留侧投票持续为['unknown']，236.036秒进入的是“左右归属不明确，启动20度观察转向”，并非带侧的弧线分离。

代码原因：audit_from_cargo把同侧绿色+橙色等组合压成unknown，left/right_invalid也可能为true；_side_is_disperse_candidate因此不允许选择该侧。当前unknown还混用了“多个已识别类别的组合”和“真正无法识别的类别”。
另外，侧投票要求侧别和该侧数量都一致，数量在1/2/3之间抖动时会反复清空，增加等待。

建议：
- 上位机内部区分known_mixture与真正unknown，保留完整检测组成供分离选择。
- 运输审核仍维持非法混装/单件规则；可尝试分离的候选规则独立判断。
- 完整证据证明目标侧有本轮合格物体、侧别可靠且满足危险处理要求时，允许受控分离，不能一概改成20度观察。
- 真正未知、危险物和无法确认归属的目标继续保守处理，不能把类别改写成绿色以绕过下位机。
- 侧别选择可按两帧稳定侧别与合格候选存在判定；夹紧已统一10度，不必仅为强夹档位强求数量完全相同。真实数量仍进入审核签名，不能通过放宽侧投票放宽运输合法性。

## 4. 视觉发布间歇停顿延长两帧审核

192752会话配置vision_fps=50，但按frame_sequence变化与日志时间估算实际约17.7帧/秒；192310约17.5帧/秒。
192752记录中相邻检测日志出现70次大于500ms的间隔，最大约787ms。日志按10fps下采样，单凭间隔不能完整推断摄像头原始帧率，但相应上位机审核事件也反复使用旧frame_sequence：例如1249在76.396至76.838秒持续重复，1250到77.041秒才出现。
这会与500ms证据有效期发生冲突，表现为一直1/2或两帧刚收集又重置。
中位推理流程耗时约19.9ms，不足以把全部停顿归咎于模型推理；应分别量测取帧、解码、make_vision_snapshot、ROI栅格化、显示及日志写入。

建议：把相机/推理发布与显示、写盘解耦；缓存ROI掩码/积分图，避免每个框重复创建掩码；记录采集时间而非重复处理旧图的时间。不要靠延长旧帧有效期冒充新证据。

## 5. 相机角度与串口上下文：证据边界

进入CAPTURE_AUDIT时“等待完整140度新画面”是通用状态提示，不等于已经证明舵机没到位。
Camera_GetAngle只返回Camera_SetAngle保存的指令角度，当前没有舵机实际角度反馈。因此报140度只能说明软件发过该目标。
此次长等待期间仍有大量清楚目标框，ROI质量门槛已能解释主要阻塞，优先处理ROI作用范围；机械安装/角度标定仍需要实物对照。

192310最终诊断还有一条独立问题：上位机APPROACH、CMD9，任务59819/action48422；下位机mode3，已接受action48421/CMD16，上位机reason=command_context_pending且disperse_attempts=1。
这说明结束时还有新接近请求未被接受，不能把所有“抓前卡住”都归因于相机。需要检查拒绝回执、frame floor、同堆任务预算和SEARCH允许接近的阶段，不能无限重发旧请求。
