# 上位机增量交接：可恢复等待与分离预算（2026-10-16）

以本文件所在下位机提交为准；上位机核对基线为codex/gamepad-teleop@0247bdd。
本文覆盖此前交接文档里“所有IMU运行故障均需重启、上位机永久锁存”的要求。
此前运动极性、T265外参、三帧审核、橙色后退和分离轨迹适配仍然保留。

## 下位机实际变更

- 单次温度/身份读取失败只记错误，不直接判废角度；FIFO状态、加速度读取失败允许后续轮询重试，不丢弃FIFO。
- FIFO数据读取中断、溢出、异常标签/时间间隔或长期无采样，暂停使用角度并自动尝试重新建立FIFO流。连续50对有效样本后恢复采样就绪，但保持heading_uncertain，不能假装找回丢失角度。
- 无效采样时在电机更新中停止输出；不会自动重放旧动作。永久掉电/传感器损坏不能保证自动恢复，但不再停止尝试。
- NormalRun对POSE/MOTOR/START超时/COMMAND超时/RAM类任务失败改为mode51可恢复等待，FAULT位和fault_code为0；STOP/ABORT仍遵循用户显式停止语义，非法状态等编程错误仍停止。
- mode51保持夹爪实际位置、不自行开爪、不增加投送计数；取消旧有限动作并清除旧审核，移动相机到审核位置。
- mode51等待恢复后的三个不同T265位姿包：有效、T265_GOOD、非UPDATE_REJECTED、tracker confidence至少2、接收年龄不超过250ms；车辆轮计数为0，位姿相邻变化不超过20mm和2度。恢复等待至少600ms后重设本地位置/航向，不清零累计路径。
- 新参考确认后CLAW_VISIBLE才为1。此标志在mode51同时表示可开始新的爪内审核，不表示载荷已合格。
- NormalRun删除“反向转角超过5度立即故障”的新增分支，仍保留带方向进度，不能把反向运动计为完成。动作超时进入mode51而非整场故障。
- 未重新启用全局堵转联停，也未取消用户STOP/ABORT。原有审核失败/分离失败恢复不变。

## 必须同步的mode51处理

1. 增加STM_MODE_RECOVERY_WAIT=51；协议帧长度、串口配对不变。旧上位机不认识51，必须先配套适配，不能仅烧录下位机后投入比赛。
2. 在context_pending、常规审核超时和通用故障锁存之前处理新鲜mode51。上位机保持当前批次、首件条件、投送计数和场上暂存记录，清掉旧pending审核、旧有限动作等待及未接受指令，不重发旧DISPERSE/YIELD/NAV/GRAB。
3. 不能把mode51等同于正常SEARCH、成功完成或空载。记录恢复原因/原阶段；FAULT=0并不代表可以立即运动。
4. 继续发送既有0x16 T265位姿。位姿必须来自真实新鲜、可信的T265更新，不能反复发送缓存位置却标T265_GOOD。姿态无效时等待恢复，不猜角度，不改变已标定的T265外参。
5. mode51 CLAW_VISIBLE=0时只发当前接受上下文的HOLD；人工PAUSE保持暂停。CLAW_VISIBLE=1后，沿原task_id新建CARGO_AUDIT action_id，建立新frame floor并进行真实爪内审核。不要重用中断前的STABLE。
6. mode51也要求本地三帧、STABLE和READY/VALID握手；将51纳入可观察审核模式和pending处理，但不要照搬17秒后ABORT的旧异常退出策略。等待过长应上报可恢复等待，不永久锁存整场。
7. 审核合法：新action_id发送GRAB_CONFIRMED。下位机重新闭爪进入抓后mode23复核，必要时重新执行伤员49/23/50流程；不得直接NAV。恢复闭爪不会重复CORE闭爪前50mm推进。
8. 审核确认空爪：新action_id发送现有RETURN_CENTER（原H/D合法字段），返中心后重新寻找。不能只凭视觉None或占位包判空。
9. 审核非法非空：可保持不动等待新的观察；需要放弃时，上位机明确发送RELEASE_BOTH。下位机才张爪、后退、闭爪并进入mode47。禁止仅因恢复等待超时自动丢弃载荷。
10. mode51不接受直接NAV/ALIGN/CLEAR/单侧RELEASE/DISPERSE，防止重启部分完成的动作。先恢复审核；新命令被拒绝时返回真实审核，不通过换task_id试探绕过。
11. 扫障或投放中断尤其不能自动标记成功。保留原物资/障碍/暂存位置；恢复后按真实载荷和场地观察重新决策，不重启原CLEAR，不重复TASK_COMPLETE或投送计数。

## 纠正0247bdd新增的上位机永久锁存

state_machine.py及run_competition_rescue.py目前看到一次fault后就保留stm_fault_waiting。
将可恢复等待与真正的显式STOP/ABORT/持续故障区分；收到新鲜mode51应退出旧的故障等待，进入上述重同步流程。
不要简单删除所有故障检查，也不要仅故障位消失就恢复旧运动；必须以实际状态、新参考和新审核为依据。
真正硬件故障持续存在时保持输出停止并持续提示，不承诺无参考也继续运动。

## 普通分离拒绝的恢复

runner现有_reconcile_transport_rejection和_reconcile_sweep_rejection保留。
补齐普通DISPERSE/RELEASE请求被明确拒绝后的路径：核对fresh、task_id、rejected_action_id和本次尚未接受状态，撤销该请求等待，重建新帧审核。
拒绝不计入分离次数，已经接受的动作不能因视觉抖动重启。尤其证据超过500ms时，不无限重发被拒绝动作等15秒下位机兜底。

## 分离次数跨任务：下位机新增约束

- 已发生分离且预算尚未通过返中心清理时，不允许用新的task_id开始目标。action_id递增及合法16位action rollover仍可使用。
- 同一堆重新识别、换track、换侧、换档，继续原task_id和总计数，不重新_select_batch分配新任务。
- 如果不能继续原上下文，应走实际放弃/返中心流程；同一task下RETURN_CENTER可用，不能靠另开任务清零。
- RETURN_CENTER确实完成并进入SEARCH后，下位机才清理旧分离预算。上位机在这次交接时同步清理旧物理尝试计数；另用失败堆记录避免立刻再次盯住同一堆，不能把历史避让记录混作新一轮下位机计数。
- mode51保留预算，恢复审核合法可重新闭爪运输；不存在通过故障恢复获得第四次分离的通道。

## 调试与手柄

- MotionDebug旧动作因IMU异常结束后不会自动续跑。等待IMU恢复采样，再在车静止时发送RESET建立新的本地零参考，随后发送新测试命令。RESET不能被解释为修复真实绝对角度。
- Gamepad恢复采样后须收到关闭使能且前进/横移/旋转均为0的新手柄帧，才确认新的手动参考；再由操作者重新使能。不会把旧摇杆指令直接续跑。
- 文本诊断新增IMU_RECOVERY ACTIVE/UNCERTAIN/COUNT，保留原FIFO诊断。不要假定这些字段进入了0x1A。
- 不变更Gamepad轴符号、NormalRun视觉PID、0x15原始编码器或T265纯定位模式。
