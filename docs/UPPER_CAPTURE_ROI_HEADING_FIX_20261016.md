# 第1、2、3项优化落地与上位机交接

本轮在F407@4385b0d及上位机codex/gamepad-teleop@81879e0基础上增量实现。下位机代码已直接修改；上位机本地副本提交为3946723，并生成[业务补丁](rdk_patches/20261016-roi-empty-capture-separation.patch)，尚未推送danmo-teng远端或部署RDK。补丁只含三个业务文件，不含测试程序。

## 1. 下位机：初次空爪继续限距接近

修改Main/Src/Task.c的task_capture_observe。

只有普通mode21或聚集mode38处于初次抓前慢爬、尚未发生分离、没有cargo_recheck_pending，且前进预算有效且未用完时，纯空爪证据才允许继续前进。纯空爪要求总数和两侧数量均为0、两侧类别均为NONE、没有危险/未知/伤员混装标志。

这解决了“摄像头刚到140度，物块尚在爪前，上位机已经看见两帧空爪，下位机却停车甚至退让”的阶段混淆。允许继续前进不等于AUDIT_VALID，不授权闭爪或运输。

同目标300mm额度、15秒审核总期限保持；连续空帧不重置或返还距离，不延长总期限。用完额度仍停车，通过现有决策/恢复路径退出。非空证据、危险或未知审核仍按原规则停车决定。mode23抓后、分离后、mode48运输复核及扫障空爪规则不变。

125/130度原地对准保留；140度稳定250ms后，普通目标180mm/s、聚集目标200mm/s慢爬。俯仰P=0.55、车头视觉P=0.18/D=0.0025保持。

## 2. 下位机：固定航向段共用10ms控制

新增任务层薄封装task_move_heading，转调用现有Motor_MoveHeading，不新建PID或更改增益。以下固定航向动作使用与MotionDebug定距直行同源的电机层10ms航向PI和加减速处理：

- 普通抓前慢爬、聚集抓前慢爬。
- 橙色半闭爪后退2秒。
- 抓取失败张爪后直线退让。
- 临时藏堆释放后直退。
- 核心物块闭爪前额外前进50mm。
- 扫障中无侧移的固定航向直线段。

目标航向在动作开始时锁定，重复调用同一目标不会每20ms重置航向积分，变速也不改变目标航向。正反向速度直接使用统一API，不重复乘方向符号。上层仍负责原有距离、时间及状态完成条件。

视觉对准、不断更新H/D的导航、曲线分离及扫障沿轨迹回退需要动态转向，保持其现有控制语义。原有ENTER固定推进已使用Motor_MoveHeading，继续保持。轮速PID=5/0.12/0、航向PI=2.2/0.005、MG310计数1061.268、60%PWM、原极性不变。

若固定航向请求被现有电机接口拒绝，使用已有mode51可恢复等待，不新增永久故障锁存。请勿把“角度不可信时允许按原方向无限运动”作为恢复方式。

## 3. 上位机必须同步的业务改动

### capture_roi.py

CaptureRois增加本地calibrated属性。缺少标定文件时默认多边形仍可用于编辑显示，但不能当作已经标定的正式夹爪ROI，审核显示capture_roi_uncalibrated。已保存的标定文件照常使用，不更改其点位和坐标系。

### run_competition_rescue.py

- 先按原底部中心+60%面积交集规则筛选每个目标；不满足者不进入夹内清单，也不再将整幅图置为无效。所有真正满足夹内条件的额外物块都要计数。
- 图像边缘截断检查只作用于已进入夹内清单的目标，仍保留这类目标的质量限制。
- 在mode21/35/37/38分离观察中，至少两个明确已知类别、未被图像边缘截断的检测可作为混合堆证据，不因检测框相互重叠统一变成None。mode23/45/48正式审核质量条件保留；INITIAL_STASH真实非空和mode43当前目标语义保留。
- audit_from_cargo增加左右侧实际类别计数元组，供本地分离选择。绿色+橙色的线上类别仍为UNKNOWN、仍属非法运输，不伪装为绿色或MIXED_MATERIAL。
- 缺图、全黑/过曝和未标定等无观察条件继续生效。

### state_machine.py

- 初次mode21/38纯空爪审核继续发送真实帧和现有两帧STABLE，不进入recheck_empty_to_search，也不发GRAB/释放；下位机决定剩余接近距离和超时出口。抓后和分离后的空爪仍进入原丢载流程。日志reason为capture_empty_approach。
- 已知混合侧只有在逐侧类别计数、绿色数量及总量证据一致时，才允许受控分离；真正unknown_present、危险物或缺少组成证据继续拒绝作为保留侧。运输合法性和目的地规则不放宽。
- 两侧均有绿色时选较多侧；相同优先保留已锁定侧，再按无关数量选择确定性回退，避免左右跳动。
- 普通抓取意外遇到多物块时，也通过原两帧侧别投票和disperse_reaudit握手进入选择性分离，不只对CLUSTER_TARGET生效。
- 已有可靠选侧时不被FIRST_GREEN_BUMP覆盖。发动作前根据当前审核更新cluster_keep_side_count，避免旧零值让SIDE_VALID丢失。
- DISPERSE_PILE+SIDE_VALID表示曲线分离；保留右侧加TARGET_RIGHT。仍遵守同堆两次、每次10度、动作完成重新取图复核、最终失败返中心规则。

上下文配对、两帧采集间隔至少100ms、先发STABLE再等READY/VALID、mode49/50及mode48、缺pending恢复、15/17秒原有期限均保持。

## 4. 应用与同步部署

请上位机Codex在当前工作分支上合并，不重套旧0007等补丁，不覆盖后续改动。补丁基线为81879e0；先确认相应改动尚未存在，再执行git apply --check。存在冲突时按三个业务文件逐段合并，不整文件替换。

在上位机仓库根目录，补丁路径按实际存放位置填写：

```sh
git apply --check /path/to/20261016-roi-empty-capture-separation.patch
git apply /path/to/20261016-roi-empty-capture-separation.patch
```

F407烧录本轮提交编译的build/NormalRun/WWW.elf，RDK部署合并后的代码并重启读取标定。只烧F407时，旧上位机仍可能因抓前空爪转入放弃，因此必须同步部署。不要修改串口消息编号、T265侧装外参、定位模式，也不要恢复通用ESCAPE。
